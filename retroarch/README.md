# RetroArch and cores: our patches and build notes

In the working tree these sit next to the built core DOLs (not in this repo). Apply on top of
[RetroArch](https://github.com/libretro/RetroArch) v1.22.2 in this order: `swiirl.patch`,
`patches/retroarch_gx_audio_align_efb_clear.patch` (the set the cabinets run), then optionally
`patches/retroarch_fastexit.patch` and `patches/retroarch_kidsafe.patch` (held: see the end). The core patches go on
fbalpha2012 (`fbalpha2012_samples_be.patch`, `fbalpha2012_i8039_be.patch`) and mame2000-libretro
(`mame2000_tilemap_be.patch`). `build/build_cores.sh` and `build/link_all.sh` run inside `devkitpro/devkitppc:20190212`
with the sources under /src. The notes below are the build log, newest change last.

# RetroArch 1.22.2, SWIIRL build (Wii)

swiirl.patch on libretro/RetroArch v1.22.2: the network command interface (UDP 55355: GET_STATUS, QUIT, ...) comes
up on a thread on the Wii, so a game starts at once even on slow Wi-Fi; getsockname stub for the 2019 libogc.
Cores (fbalpha2012, fbalpha2012_cps1/cps2/neogeo, mame2000) from libretro master, all built with
devkitpro/devkitppc:20190212 (newer toolchains clash with RetroArch's bundled Wii libraries), linked with
    make -f Makefile.griffin platform=wii GX_PTHREAD_LEGACY=0 HAVE_NETWORKING=1 HAVE_NETWORK_CMD=1 HAVE_COMMAND=1
on the Linux build box (~/ra-build: build_cores.sh, link_all.sh). The salamander boot.dol stays the stock one.
Tested in the simulator: Pac-Man GET_STATUS -> "PLAYING ,pacman,crc32=...", QUIT -> back out.

2026-10-16: three more cores, same toolchain and link line (build_cores.sh / link_all.sh build and link all 8):
genesis_plus_gx (libretro/Genesis-Plus-GX aa74d79, master), fceumm (libretro/libretro-fceumm ac0d00a, master),
snes9x2010 (libretro/snes9x2010 097deba, 2026-08-07: master fe690dd needs rinflate_* from a newer libretro-common
than RetroArch 1.22.2 has, used by the .msu1 pack reader added in the next commit 7d3c3de).
Autotest (runloop.c, Wii only): if sd:/arcade/autotest holds a positive integer N, RetroArch quits N seconds after
content starts running, through the normal quit path (RUNLOOP_STATE_QUIT -> CMD_EVENT_QUIT, back to the launcher).
Missing or invalid file: no change. RetroArch only reads the file; the launcher creates and removes it.
link_all.sh now deletes griffin/griffin.o first (Makefile.griffin does not track the files griffin.c includes).

2026-10-16 (later): genesis_plus_gx and snes9x2010 fixed (both DOLs above replaced; the two from earlier did not work).
- genesis_plus_gx: now libretro/Genesis-Plus-GX e48a3717 (2025-11-21, RetroArch 1.22.2 era) built with
  -DUSE_DYNAMIC_ALLOC added to the Wii section of Makefile.libretro (build_cores.sh applies it with sed; WiiU
  already has it). Cause: without it the 15.8 MB cart/CD union `ext` (MAXROMSIZE 15 MB) is static bss, the DOL's
  bss ran 0x806c3620-0x819f9c40, past the end of MEM1 (0x81800000), so the DOL died before RetroArch's log started.
  Now ext is calloc'd from RetroArch's MEM2 heap; bss ends at 0x80adece0. (Master has the same Makefile, so the
  same problem; it is the 15 MB static buffer, not the core version.)
- snes9x2010: now libretro/snes9x2010 f9ae8fd (2024-11-19, the long-standing version). Cause: the 2026 commits
  bundle a newer libretro-common whose memstream_open(data, size, writing) clashes with RetroArch 1.22.2's
  memstream_open(writing) when statically linked: griffin.o's definition wins, the core's ROM stream gets no
  buffer, and LoadROM fails ("ROM: Unable to load ROM"). f9ae8fd uses the same memstream API as RetroArch 1.22.2.
  Lesson: a core statically linked into this RetroArch must use libretro-common APIs that match RetroArch 1.22.2.
- ~/ra-build/build_two.sh rebuilds + relinks just these two (griffin.o reused).
- Simulator (atest2.py, slots 5/6): mdsonc2.md, mdsor2.md, mdgunst.md, snsmw.sfc, sndkc.sfc, sntmnt4.sfc all
  "loaded": core runs, geometry/audio set, no core errors, autotest quit after 5-10 s of content, clean unload.

## 2026-10-16: Donkey Kong sound fix
fbalpha2012: src/cpu/i8039/i8039.cpp I8039_PAIR byte order for big-endian (MSB_FIRST) — the i8039 sound CPU
pushed byte-swapped return addresses on the Wii, so dkong / dkongjr had no music (found with Dolphin audio dumps,
~/wii-sim/fix/i8039-bigendian.patch, applied in ~/ra-build; single-core relink: ~/ra-build/fba_fix.sh).

## 2026-10-17: A/V fix (see videos/av_fix/findings.md, patches/)
- gx_audio.c: 32-byte-aligned DMA chunks; misalignment caused a 500 Hz click on every game.
- gx_gfx.c: the EFB is cleared at every mode set and every frame, so no stale image from the previous program.
- mame2000 tilemap.c: memcpybitmask8/16 was little-endian only (gng, commando, pacmania, galaga88 text was shredded).
- fbalpha2012 samples.cpp: 16-bit WAV samples are byte-swapped on big-endian.
- Per-game native-resolution overrides (sdkit/retroarch/config, generated by videos/av_fix/make_overrides.py).

## 2026-10-17: fast exit + WIIZARD loading screen (patches/retroarch_fastexit.patch, on top of the A/V fix)
- frontend/drivers/wiizard_wii.c: a terminal loading screen ("> LOADING <TITLE>" + a byte-progress bar) from the
  top of frontend_gx_init until gx_init; launcher-started runs skip RetroArch's own IOS reload (keeps AHBPROT).
- Quitting (menu, L+R+Z+START, network QUIT, autotest) shows "> RETURNING TO WIIZARD" and execs
  sd:/apps/wii-agent/boot.dol --relaunch=game [--game-ran] [--autobooted] directly, with the AHBPROT patch
  applied first: no System Menu/Priiloader/hop round trip. Pairs with launcher 0.9.21.
- Simulator: dkong in 7.0 s (was 14.1), back in the menu 2.1-2.3 s after quitting. Not yet on hardware.
  Details: videos/fastexit/. The previous (A/V fix) set is in sdkit/retroarch-swiirl-avfix-backup/.

## 2026-10-17: kid safety + idle quit (patches/retroarch_kidsafe.patch, on top of fast exit)
- RESET during a game quits back to WIIZARD (was: RetroArch's menu with Close/Load Content and save states).
- POWER unloads the game (saves .hi/.nv/.srm) and powers the console off (was: back to WIIZARD).
- Idle quit: no pad change for WZ_IDLE_MINUTES (15; 1 when sd:/arcade/idletest exists) -> back to WIIZARD, whose
  own idle power-off then follows. Launcher-started runs only; the autotest timer is separate.
- Simulator (Mac Dolphin, launcher 0.9.21): dkong / snsmw idle-quit at 60 s with the test file, input resets the
  timer, RESET back in the menu in 1.1 s, POWER saved snsmw.srm then powered off. Evidence videos/fastexit/kidtest_logs.
  Previous (fast-exit) set: sdkit/retroarch-swiirl-fastexit-backup/. Our Nintendont got the same 15-min idle exit
  (sdkit/nintendont-swiirl.dol; previous one nintendont-swiirl-prekid.dol).
